# Source Summaries

This file summarizes the source pack behind Agent Mode. It is intentionally concise: each entry tells an agent what the source is useful for, what it complicates, and how safely it can be used.

## Source Status

- `public`: safe to link publicly after URL verification.
- `public-safe-summary`: safe as a summary, but do not link raw private material.
- `needs-provenance`: useful idea, but exact source, quote, date, or method still needs checking.
- `approval-required`: do not publish concrete details until the relevant owner approves.

## 1. Dan's Draft History And Live Argument

- **Status:** public-safe-summary.
- **Useful for:** preserving the essay's actual thesis: AI progress is real, but the meaning of that progress depends on how work is framed, reviewed, and owned.
- **Complicates:** the simple "AI replaces knowledge work" narrative.
- **Agent use:** when summarizing, preserve the paradox: Every uses AI aggressively and still has more human work to do.

## 2. Every Inside-View Anomaly

- **Status:** public-safe-summary.
- **Useful for:** showing that the essay is not abstract punditry. Every is living the shift through coding agents, Proof, agent-native product work, support workflows, events, and launch systems.
- **Complicates:** any claim that AI adoption simply means less human work.
- **Agent use:** ask what new review, framing, and compounding work appears after agents enter the workflow.

## 3. Fin, Waqqas, And Customer Support

- **Status:** approval-required for metrics and identifying details; public-safe-summary for the pattern.
- **Useful for:** separating stable-frame automation from frame-collision human work.
- **Complicates:** easy customer-service automation stories.
- **Agent use:** use as a pattern, not a universal proof. Do not cite exact metrics unless approved.

## 4. Senior Engineer Benchmark

- **Status:** needs-provenance for exact scores, model names, run dates, prompts, and scoring.
- **Useful for:** explaining how benchmarks can smuggle in human framing.
- **Complicates:** naive leaderboard readings.
- **Agent use:** focus on the prompt/frame lesson unless exact benchmark packet details are available.

## 5. GDPVal And Expert-Task Benchmarks

- **Status:** public, final URL/methodology should be verified before launch.
- **Useful for:** showing that benchmark prompts often include role, objective, inputs, constraints, sample criteria, and output shape before the model begins.
- **Complicates:** claims that benchmark performance equals autonomous expert ownership.
- **Agent use:** ask what work the task author already did for the model.

## 6. METR Time Horizons

- **Status:** public, exact row/date should be verified before launch.
- **Useful for:** making frontier progress concrete.
- **Complicates:** complacent arguments that AI progress is fake or stagnant.
- **Agent use:** pair with a frame analysis: what does the benchmark measure, and what does it leave out?

## 7. Humanity's Last Exam

- **Status:** public, dated leaderboard should be verified before launch.
- **Useful for:** demonstrating real progress on difficult academic-style questions.
- **Complicates:** any attempt to wave away model capability.
- **Agent use:** use as evidence of progress, not evidence that all expert work has been automated.

## 8. Worker Field Notes

- **Status:** mixed; public-safe-summary until quotes and URLs are reviewed.
- **Useful for:** grounding the labor story in admin, customer support, translation, design, legal support, sales, technical writing, and broadcast/voice work.
- **Complicates:** both naive optimism and naive doom. Outcomes include replacement, augmentation, degradation, new supervision work, and new expert leverage.
- **Agent use:** return the optimistic, pessimistic, and worker-level interpretations separately.

## 9. Hidden Work After AI Replacement

- **Status:** public-safe-summary.
- **Useful for:** naming work that reappears as QA, escalation, prompt maintenance, knowledge-base maintenance, manager review, customer repair, or engineering cleanup.
- **Complicates:** headcount-only analyses.
- **Agent use:** when a reader says "AI will automate this," ask what new hidden work appears downstream.

## 10. Compound Engineering

- **Status:** public.
- **Useful for:** showing an operating model where agents produce work and teams compound the learning into guides, prompts, reviews, repos, and tools.
- **Complicates:** the idea that agent work is only one-off delegation.
- **Agent use:** turn any recommended workflow into a reusable artifact.

## 11. Agent-Native Product Management

- **Status:** public.
- **Useful for:** showing that non-engineers can work with coding agents and agentic tools when the interface is structured around artifacts, specs, and review.
- **Complicates:** the idea that the agent future belongs only to engineers.
- **Agent use:** ask what artifact the reader should create with an agent, not just what chat answer they want.

## 12. Codex As Knowledge-Work Operating System

- **Status:** public.
- **Useful for:** showing that coding-agent interfaces can become daily drivers for non-engineering knowledge work: planning, inbox work, KPI review, recruiting, research, business documents, and small tools.
- **Complicates:** the "developer tools are only for developers" assumption.
- **Agent use:** ask what recurring workflow should move into a folder with instructions, source files, connectors, and review criteria.

## 13. Dan's Inbox-Zero Codex Workflow

- **Status:** public.
- **Useful for:** demonstrating visible delegation: the agent acts in the inbox, but drafts and decisions live in a Proof document where the human can review them.
- **Complicates:** blind automation. The human remains the accountable reviewer.
- **Agent use:** recommend an operating manual before any inbox automation.

## 14. Mining Scattered Thinking Before Drafting

- **Status:** public.
- **Useful for:** turning Slack, Notion, Drive, transcripts, notes, and recordings into a grounded outline before drafting.
- **Complicates:** generic AI writing. The best draft starts from what the human has already thought.
- **Agent use:** ask the agent to cite the human's prior statements and group the strongest threads before writing.

## 15. Agent Watchdog Workflows

- **Status:** public.
- **Useful for:** bounded recurring monitoring tasks, such as scanning a curated security feed and reporting relevant issues.
- **Complicates:** open-ended "watch everything" agent fantasies.
- **Agent use:** define source set, cadence, relevance rules, output format, and human owner.

## 16. The Folder Is The Agent

- **Status:** public.
- **Useful for:** showing why agent-ready work often means project folders, local instructions, source docs, and durable context.
- **Complicates:** one-off chat workflows that lose state.
- **Agent use:** recommend a folder structure and reading order before complex work.

## 17. Confidence Check Before Shipping

- **Status:** public.
- **Useful for:** adding a lightweight review gate to agent work before PRs, docs, campaigns, or customer-facing artifacts ship.
- **Complicates:** both blind trust and endless polish. The confidence check forces uncertainty into the open without pretending to guarantee correctness.
- **Agent use:** ask the agent to score confidence, justify the score, name unresolved risks, and revise if below threshold.

## 18. Recent Steal This Workflow Examples

- **Status:** public.
- **Useful for:** giving readers concrete, recent workflows they can copy: mine scattered thinking before drafting, write evals before agent skills, run inbox review through Codex plus Proof, convert support feedback into a product queue, ask Codex what to automate from real tool usage, storyboard product videos from screen recordings, and create bounded security-monitoring agents.
- **Complicates:** vague claims that Every "uses agents" without showing the operating details.
- **Agent use:** recommend one small workflow the reader can try this week, then name the human frame, agent execution step, review surface, and reusable artifact.

## 19. Team Agents With Defined Jobs

- **Status:** public.
- **Useful for:** showing that Every's agent practice is not naive boosterism. The first personal-agent rollout created upkeep and reliability problems, which pushed the product direction toward shared agents with defined team jobs.
- **Complicates:** the idea that every employee should automatically get a general-purpose personal agent.
- **Agent use:** before recommending an agent rollout, ask what recurring job the agent owns, what source of truth it reads, what actions it can take, and how the team evaluates success.

## 20. Same Voice, RLHF, And Model Compliance

- **Status:** needs-provenance for exact papers and links.
- **Useful for:** explaining why model output often converges toward generic, agreeable, average-seeming answers.
- **Complicates:** the assumption that more model capability automatically creates more difference.
- **Agent use:** connect sameness to demand for taste, voice, and expert judgment.
